# 일별·주별·띠별 해설 반복 개선

## 확인한 원인

- 개인 운세는 분야·점수대별 도입과 조언이 각각 2개뿐이었다. 주간도 일간과 같은 문장 조합을 사용해 요일별 차이가 분야 해설에 반영되지 않았다.
- 제목은 가장 높은/낮은 분야에만 연결되어, 같은 분야가 우세한 여러 주에 같은 제목이 이어졌다.
- 띠별 일간은 지지 관계·지지 오행·점수대의 문장만 조합했다. 같은 근거의 띠는 문단 전체가 같아지기도 했고, 계산에 사용한 천간 오행은 요약에 드러나지 않았다.
- 띠별 월간이 일간 문장을 재사용해 “오늘”, “내일”, “하루”가 포함되었다.
- 문구 순환 길이가 12지·60갑자 주기의 약수이면 같은 간지가 돌아올 때 같은 장면이 선택되는 문제도 확인했다.

## 변경 범위

- `src/content/reading-actions.js`: 7개 분야 × 6개 생활 장면, 적극적인 활용과 신중한 활용, 한국어·영어 문구를 같은 원본으로 관리한다.
- `src/domain/reading.js`: 실제 해석 요인에 맞는 장면 선택, 날짜·주차 순환, 전날 대비 점수 차이, 7일의 강약·동점 처리, 띠별 관계·오행 설명을 담당한다. 조회 이력이나 난수를 사용하지 않는다.
- `src/engine/fortune.js`: 일간은 당일 일진의 요인을 우선 설명하고 실제 전날 대비 점수를 덧붙인다. 주간은 분야마다 요일별 최고·최저와 주초/후반 흐름을 설명한다. 개인 월간·연간의 기존 해설 방식은 유지한다.
- `src/engine/tti.js`: 일간·연간 제목/분야 조언·월간 해설에 장면을 연결한다. 같은 계산 근거를 가진 띠의 활용 예시는 서로 다른 순서로 배정하되, 근거 자체나 점수는 바꾸지 않는다. 월간에는 해당 월 점수에 사용하지 않는 천간 해석을 새로 추가하지 않는다.
- `src/site/pages/share.js`: 새 제목 허용 목록을 같은 문구 원본에서 파생한다. 기존 공유 제목과 한영 전환도 계속 지원한다.
- `tests/reading-variety.test.js`, `tests/browser/reading-variety.spec.js`: 점수 보존, 반복, 기간 표현, 실제 화면 연결을 검증한다.

계산 가중치·점수 환산·달력·오행 관계·신살·기존 골든값은 변경하지 않았다. 생활 장면은 해석을 활용하는 예시이며 서로 다른 사건이 발생한다고 예측하기 위해 추가한 변수가 아니다.

## 표본 비교

개인 표본: 양력 1993-01-28 03:40, 여성. 시작일 2026-10-19. 띠 표본은 12띠 전체다.

| 확인 항목 | 수정 전 | 수정 후 |
| --- | ---: | ---: |
| 30일간 개인 일간 제목 종류 | 9 | 19 |
| 12주간 개인 주간 제목 종류 | 2 | 9 |
| 12주간 분야별 문단 종류 | 6~10 | 각 12 |
| 10월 19일의 띠별 문단 종류 | 11 | 12 |
| 30일 × 12띠에서 가장 많이 반복된 행동 조언 | 86회 | 24회 |

제목·문단 종류는 문자열 기준이다. 특히 개인 일간 문단에는 실제 전날 대비 점수 차이가 들어가므로, 문단이 다르다는 사실을 모두 새로운 해석 주제가 생긴 것으로 해석하지 않는다. 같은 오행·관계 근거는 정확성을 위해 반복해서 설명할 수 있다.

추가 표본에서 60일간 같은 날짜의 12띠 문단 중복이 0건이었다. 12띠 × 시작일 60개를 각각 60일 뒤와 비교한 720쌍에서도 첫 행동 조언이 그대로 재선택되지 않았다. 이 결과는 모든 미래 날짜에서 모든 문장이 중복되지 않는다는 보장이 아니다.

## 재현 및 검증

- 수정 전 주간 제목 반복, 띠별 동일 문단, 월간의 일간 표현 테스트가 실패했고, 수정 후 통과했다.
- 60일 재방문 시 같은 장면 선택 문제도 실패를 재현한 뒤 수정했다.
- 점수 보존: 서로 다른 개인 입력 3개 × 60일의 일간·주간 총점/분야/요일 점수, 12띠 × 60일의 일간 점수, 2026·2027년 띠별 연간/분야/연생/월간 점수의 수정 전 SHA-256과 일치한다.
- 주간 최고·최저 동점, 전체 동점, 분야별 반대 추세, 비정상 데이터 거부를 검증한다.
- 오늘·내일·주간 입력 화면, 띠 목록·상세·모달, 연생 선택 뒤 월간 해설을 한국어·영어에서 엔진 결과와 대조한다.
- 새 제목 전체의 양방향 언어 전환과 기존 공유 제목, 임의 제목 거부를 검증한다.
- 최종 `npm run test:all`: 단위·사이트 테스트 110개, 브라우저 테스트 95개, 총 205개 통과. 실패 0개.
- 최종 `npm run lint`: 통과. `npm run build`: 한국어·영어 404페이지 생성 성공. `git diff --check`: 통과.

## 한계와 보존 상태

- 정해진 해석 근거와 문구를 사용하므로 일부 설명은 반복된다. 점수 차이를 인위적으로 늘리거나 같은 근거를 다른 사실로 표현하지 않는다.
- 문구 추가로 계산 화면 JS 번들이 약 498.20KB → 518.27KB, gzip 약 155.09KB → 163.27KB로 증가했다. 빌드는 성공하지만 Vite의 500KB 크기 경고가 발생한다. 기존 main 코드를 임시 빌드에 주입해 비교했으며 사용자 파일은 되돌리지 않았다.
- 수동 육안 검수, 운영 배포, 기존 이미지·영상 재생성은 수행하지 않았다.
- 작업 브랜치: `codex/fortune-reading-variety`. 종료 전 `git fetch origin main` 재확인 결과 `origin/main` 대비 앞선/뒤처진 커밋은 0/0이다. 변경은 미커밋이며 커밋·push·PR 생성은 하지 않았다.
- 기존 `AGENTS.md`, `START_HERE.txt`, `Creative/`, `videos/`, `output/`, `docs/search-audit-2026-10-15/` 미추적 자료는 그대로 보존했다. `.agents/`는 수정하지 않았으며 `.legacy-local/`은 접근하지 않았다.
