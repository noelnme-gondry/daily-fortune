## 글자와 화면 구성

직접 확인한 데스크톱 화면에서 신한은 OneShinhan 계열의 제목 40px·행간60px, 섹션 제목24px·행간36px이었다. 척척은 Pretendard 계열의 소개 본문16.8px·행간28.9px, 명식표 항목16px, 주요 계산 버튼22.4px였다. 특정 글꼴을 복제하기보다 본문과 표의 용도를 나누는 참고값으로 사용한다.

포춘의 IBM Plex Sans KR 본문과 Hahmlet 제목을 유지한다. 관리 화면의 입력은16px, 주요 조작은44px 이상으로 잡고, 결과 문단은 큰 글씨에서18px·행간1.85로 읽게 한다. 작은 화면에서 큰 표가 넘치면 표 안에서 가로로 이동하게 하며 페이지 전체는 넘치지 않게 한다.

저장한 사람은 모든 페이지의 주 메뉴에서 열 수 있다. 계산 폼 위의 선택 목록과 결과의 ‘다른 사람 선택’을 함께 두어 길게 읽다가도 가족을 바꿀 수 있다. 첫 저장 후에는 저장한 사람 메뉴의 위치와 사용법을 한 번 알려 준다. 화면을 모달로 열기 때문에 개인 목록에 별도 검색 노출용 주소를 만들지 않는다.

## 광고 기반 운영에서 볼 지표

우선 저장 후 다시 온 사용자가 입력을 건너뛰고 결과까지 가는지, 한 방문에서 서로 다른 운세를 얼마나 이용하는지 확인한다. 인물 이름·생년월일·관계는 분석 이벤트에 넣지 않는다. 현재 결과 도달·재계산·달력 상세·다른 운세 이동 이벤트를 활용하고, 필요하면 개인정보 없는 저장/선택 행동만 추가한다.

광고 노출과 결과 도달은 함께 본다. 결과 위 광고가 더 보이더라도 계산 결과를 읽기 전에 나가는 사용자가 늘면 이용 경험이 나빠질 수 있다. 신규 기능의 매출 기여는 배포 후 재방문과 사용량, 광고 성과를 함께 측정하기 전에는 추정 불가다.

## 구현 범위와 검증

이번 구현은 로컬 브랜치 `codex/fortune-profiles-reference-20261105`에 있다. 저장소 `ohaeng-profiles`의 기존 버전과 `profiles` 저장소를 유지하고 이름별 목록을 추가했다. 동의 없는 예전 localStorage 입력은 영구 목록으로 옮기지 않으며, 토정비결의 별도 저장 계약도 유지한다.

주요 변경은 `src/client/profile.js`, 사람 관리·읽기 설정 모듈, 공유 출생 입력 폼, 공통 내비게이션, 사주·토정비결 연결, 스타일과 한국어·영어 저장 안내다. 이어서 `reading-navigation.js`와 `chart-basis.js`를 추가했다. 계산 상수를 공통 모듈로 옮기고 근거 메타데이터를 반환하지만 계산식·골든값은 유지했다. 여러 사람 선택과 실제 결과, 편집·삭제, 기존 저장본 이관, 음력 윤달·시진, 저장 차단, 작은 화면·영어·키보드 동작을 브라우저 테스트에 추가했다.

첫 단계 검증에서 `npm run test:all`의 계산·페이지 테스트 163개와 브라우저 테스트 177개가 모두 통과했다. 이후 기간 이동·계산 근거 검증 결과는 [추가 검증 기록](fortune-interpretation-validation-2026-11-05.md)에 남긴다. `npm run lint`, `npm run build`도 통과했으며 470개 페이지와 검색용 파일이 생성됐다. 320px 한국어·영어 화면, 키보드로 관리 창 닫기, 실제 선택 인물의 결과 변경, 저장 실패 시 계산 유지까지 확인했다. 예시 화면은 [사람 관리](fortune-people-2026-11-05.jpg), [기간 이동](fortune-period-2026-11-05.jpg), [계산 근거](fortune-basis-2026-11-05.jpg)에서 볼 수 있다.

위 결과는 구현 단계의 로컬 검증 기록이며 배포 환경 검증과 구분한다. 로그인 이후 경쟁 서비스와 모바일 앱, 해외·절입 경계의 외부 대조는 후속 검증 범위로 남는다. 사람 정보는 해당 브라우저의 IndexedDB에 저장되며 기기 간 동기화되지 않고 사이트 데이터를 지우면 사라진다.
