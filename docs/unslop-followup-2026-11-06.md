# Fortune 추가 화면 검수와 수정

2026년 11월 6일 한국 시간 기준으로 최초 unslop 점검에서 남았던 본문과 하단, 펼침과 상세창, 계산 후 상태, 다른 브라우저와 외부 자산의 검증 범위를 확대했습니다. 재현한 화면 문제를 수정했으며 계산 엔진과 골든값, 점수와 순위 계산은 유지했습니다.

브랜치·커밋·배포 상태는 머지 전 로컬 검수 당시 기준입니다.

## 확인하고 수정한 문제

| 위치 | 재현한 문제 | 수정 |
| --- | --- | --- |
| 공통 홈 로고 | 화면의 서비스 설명이 읽는 이름에서 빠졌습니다. | 불필요한 aria-label을 제거해 화면 문구로 이름을 구성합니다. |
| 만세력 오행 글자 | 밝은 지면의 토 글자는 대비 4.25:1, 오늘 행의 목 글자는 4.03:1로 작은 글자 기준에 미달했습니다. | 토와 목의 밝은 테마 색을 조정했습니다. |
| 띠별 주간 등급 | 오늘 행의 강조 규칙이 대길 등급 글자색까지 덮었습니다. | 강조 대상을 첫 날짜 문구로 한정했습니다. |
| 띠 궁합표 | 높은 점수 칸의 진한 배경에서 숫자 대비가 부족했습니다. | 숫자를 유지하며 배경 농도 범위를 줄였습니다. |
| 월간 결과 달력 | 중간색 배경에서 날짜·간지·점수 대비가 부족했습니다. | 배경 농도를 줄이고 주요 날짜는 테두리로 구분합니다. 범례도 같은 색상 배율을 사용합니다. |
| 원국의 작은 표기 | 영문 보조 글자와 한글 중심 모드의 작은 한자가 오행 배경에 묻혔습니다. | 작은 글자는 본문 글자색을 사용합니다. 영문 보조 표기는 11px로 확대했습니다. |
| 긴 표와 대운 그래프 | 일부 만세력·삼재·십신·신살·토정비결·공개 예시 표와 대운 그래프에 키보드 진입점이 없었습니다. | 스크롤 구역에 이름과 포커스 진입점을 추가했습니다. JavaScript를 끈 표에서도 방향키 이동을 확인했습니다. |
| 날짜와 주요 시기 버튼 | 화면에 있는 간지·요일·선정 이유 등이 읽는 이름에서 빠졌습니다. | 화면 문구를 읽는 이름으로 사용하고 기존 짧은 설명은 title로 유지했습니다. |
| 랭킹 페이지 번호 | 한국어 읽는 이름에서 숫자가 단어와 붙어 있어 자동 검사와 음성 입력에서 표시 숫자를 구분하기 어려웠습니다. | 숫자와 페이지 단어를 분리했습니다. 번호와 이동 계약은 유지했습니다. |

WebKit의 방향키 검증에서는 키를 누르자마자 떼는 입력이 네이티브 스크롤을 취소하는 현상도 분리해 재현했습니다. 작은 독립 표와 실제 화면에서 누름 시간 100ms를 주면 이동했습니다. 앱에 별도 방향키 동작을 덧붙이지 않고 테스트 입력을 보완했습니다.

## 전체 경로의 본문과 하단

470개 한국어 및 영어 경로 각각을 320px·1440px 폭과 밝은 화면·어두운 화면에서 검사했습니다. 총 1,880회이며, 펼침 버튼과 details를 열고 본문 끝까지 이동한 상태를 포함합니다.

| 검사 항목 | 횟수 또는 결과 |
| --- | --- |
| 경로와 화면 조건 조합 | 1,880회 |
| 공통 펼침 버튼 열린 상태 | 5,280회 |
| details 열린 상태 | 3,168회 |
| 공개 상세창 열기와 크기 | 480회 |
| 문서 가로 넘침과 숨겨진 글자 잘림 | 검출 0건 |
| 푸터에 도달할 수 없는 화면 | 0건 |
| 브라우저 실행 오류 | 0건 |
| axe-core 4.14.0의 WCAG A 및 AA 규칙 위반 | 검출 0건 |

자동 접근성 검사는 `wcag2a`, `wcag2aa`, `wcag21a`, `wcag21aa` 태그를 사용했습니다. 이 결과가 수동 보조기기 검증을 포함한 접근성 인증을 뜻하지는 않습니다.

## 계산 후 상태와 상세 콘텐츠

- 오늘·내일·주간·월간·연간·평생·궁합·캐릭터·랭킹·만세력·토정비결 11개 계산기를 한국어와 영어, 밝은 화면과 어두운 화면에서 검사했습니다. 기본 결과 44개 상태와 글자 크게·한글 중심 설정 44개 상태를 확인했습니다.
- 직업 도감 60종, 아홉 인생 챕터, 명예의 전당 6개 분야의 20페이지를 언어와 테마별로 순회했습니다. 상세창 2,676회에서 열기, 제목 존재, 가로 잘림, 화면 높이를 확인했습니다. 공통 키보드 열기·닫기·포커스 복귀는 브라우저 회귀 테스트로 검증했습니다.
- 툴팁 144회의 위치와 크기, 프로필 관리의 빈 상태와 편집 상태, 빈 공유·잘못된 공유·404 화면을 추가 확인했습니다. 선택한 52개 추가 상태의 접근성 검사와 상세창 크기 검사에서 추가 문제는 검출되지 않았습니다.
- 잘못된 날짜·미입력·미래 생일, 저장소 차단과 복원, 궁합 검색 실패와 재시도, 광고 실패, 공유 취소와 이미지 저장은 기존 전체 사용자 흐름 테스트에 포함했습니다.
- 홈·오늘 결과·캐릭터의 최초 육안 확인에 더해 달력, 평생 주요 시기, 궁합, 랭킹, 큰 글자와 한글 중심 원국, 토정비결, 띠 궁합표, 이용 가이드를 육안 확인했습니다. 같은 템플릿의 모든 경로를 각각 수동으로 읽은 것은 아니며, 전체 경로의 구조와 펼침 상태는 위 자동 검사로 확인했습니다.

## 브라우저와 빌드 검증

| 검증 | 결과 |
| --- | --- |
| 단위 및 사이트 테스트 | 166개 통과 |
| Chromium 전체 브라우저 테스트 | 204개 통과 |
| WebKit 전체 브라우저 테스트 | 204개 통과 |
| Firefox 전체 브라우저 테스트 | 199개 최초 통과, 좌표 오차 검사 보완 후 나머지 5개 재검증 통과 |
| 새 접근성 회귀 테스트 | 세 엔진에서 14개씩 총 42개 통과 |
| lint | 통과 |
| 운영용 빌드 | 470페이지 생성 통과 |
| 빌드된 앱의 실제 이용 흐름 | 세 엔진과 두 언어의 6개 조합 통과 |
| diff 공백 검사 | 통과 |

빌드된 앱에서는 홈 입력과 저장, 오늘 결과, 월간 날짜 상세, 캐릭터 상세의 키보드 조작과 포커스 복귀, 랭킹 진입을 확인했습니다. 단순한 순수함수 검사와 구분해 실제 화면 연결을 검증했습니다.

단위·사이트 테스트 166개와 브라우저별 204개씩 총 778개 시나리오를 검증했습니다. Firefox의 실패 5개는 배너 높이가 320px 대신 319.99988px처럼 반환되는 좌표 반올림 차이였습니다. 높이 비교에 0.005px 미만의 허용 오차를 적용한 뒤 5개가 모두 통과했습니다. 실제 배너 크기와 앱 배치는 변경하지 않았습니다.

실제 Mac Safari에서도 390px 반응형 화면을 열어 본문과 표를 확인했습니다. [Playwright WebKit](https://playwright.dev/docs/browsers)은 실제 iPhone Safari와 같은 검증 범위가 아니므로 별도로 구분합니다.

## 글꼴과 이미지와 광고

- Hahmlet 500·600, IBM Plex Sans KR, Noto Serif KR의 실제 글꼴 다운로드와 로드 성공을 확인했습니다. 검사 중 글꼴 요청 실패는 없었습니다.
- `public/`와 `assets/`의 PNG·JPEG·WebP·SVG 이미지 148개를 디코딩했고 오류는 없었습니다. 파비콘 ICO는 기존 브라우저 이미지 로드 테스트에서 확인했습니다.
- 실제 Mac Safari와 로컬 운영용 빌드에서 쿠팡 공식 SDK의 광고 프레임이 로드되는 것을 확인했습니다. 광고를 클릭하거나 구매하지 않았습니다. 광고 차단·실패 시 기능 유지와 지면 크기는 별도 브라우저 테스트로 확인했습니다.
- 운영 도메인은 이 환경의 DNS에서 `0.0.0.0`으로 응답해 직접 브라우저 접속이 거부됩니다. 외부 DNS 조회에서는 공인 주소가 반환되고 웹 조회에서도 페이지 응답이 있어 전역 서비스 장애로 단정하지 않았습니다. 운영 도메인의 실제 광고 송출 화면은 미확인입니다.

## 로컬 성능 측정

운영용 빌드의 홈을 Lighthouse 기본 모바일 조건으로 한 번 측정했습니다. Google Fonts와 쿠팡 SDK를 실제로 요청했고 AdSense는 비활성화했습니다.

| 지표 | 측정값 |
| --- | --- |
| 성능 점수 | 94 |
| 접근성 점수 | 100 |
| 권장사항 점수 | 77 |
| FCP와 LCP | 각각 약 2.52초 |
| CLS | 0.0205 |
| 전체 차단 시간 | 11ms |

권장사항 점수에는 쿠팡 SDK의 제3자 쿠키와 관련 브라우저 경고가 반영됐습니다. Google Fonts 스타일시트의 렌더 차단도 측정됐습니다. 이 수치는 로컬의 단일 실험실 측정이며 실사용자의 속도나 운영 Core Web Vitals를 대신하지 않습니다.

의존성 검사에서는 운영 의존성의 알려진 취약점이 0건이었습니다. 개발 도구에는 moderate 권고 5건이 남아 있습니다. ESLint 관련 메이저 버전 변경 등을 UI 수정과 함께 수행하지 않았으며 `package.json`과 잠금 파일은 보존했습니다.

## 주요 수정 파일

- `src/styles/main.css`: 달력과 표의 대비, 오행 글자색, 작은 원국 표기, 띠 주간 강조 범위.
- `src/site/layout.js`: 로고 링크의 읽는 이름.
- `src/site/pages/manse.js`, `saju.js`, `tojeong.js`, `tti.js`, `src/site/public-examples.js`: 긴 표의 키보드 진입과 구역 이름.
- `src/client/views.js`, `life-events-view.js`, `life-tool.js`, `ranking-pagination.js`: 결과 버튼 이름, 달력 범례, 대운 그래프 진입점, 페이지 번호.
- `tests/browser/expanded-accessibility.spec.js`, `tests/browser/helpers/contrast.js`: 실제 계산 결과와 작은 글자 대비, 표시 문구와 읽는 이름, JavaScript 없는 가로 표의 회귀 검사.
- 기존 브라우저 테스트: 보완된 읽는 이름 기대값과 WebKit 방향키 입력을 반영했습니다.

## 보존 상태와 남은 범위

브랜치는 `codex/unslop-site-review`이며 최종 fetch 기준 `origin/main`과 커밋 차이는 앞섬 0개, 뒤처짐 0개입니다. 변경은 미커밋이며 커밋·push·PR·운영 배포는 수행하지 않았습니다.

기존 `.gitignore` 수정, `docs/character-downfall-preview.png` 삭제 상태, `AGENTS.md`, `START_HERE.txt`, `Creative/`, `output/`, `videos/`와 이전 랜딩·검색 조사 자료를 보존했습니다. `.agents/`, 계산 엔진과 도메인 계산, 패키지 파일은 변경하지 않았으며 `.legacy-local/`에 접근하지 않았습니다.

실제 iPhone·Android 단말 검사는 수행하지 못했습니다. 운영 도메인의 실제 송출 확인도 위 DNS 제한으로 남아 있습니다. 이 두 범위를 완료로 표시하지 않았습니다.
