# 사이트 크리틱 — 디자인 · 분석 · 퍼널 (2026-11-14)

## 점검 범위와 한계

- **방법**: `npm run build`로 만든 빌드를 로컬 서버(`GA_MEASUREMENT_ID=G-TEST12345`)로 띄우고, Playwright Chromium으로 모바일(390×844)과 PC(1440×900)를 확인했다. 홈 입력 → `/today/` 결과 → 공유 → `/share/` 랜딩, 랭킹 공개, 인생 캐릭터, 저장한 사람까지 직접 실행하고, 이때 `dataLayer`에 쌓인 이벤트를 수집했다.
- **한계**
  - 운영 도메인과 GA·쿠팡·애드센스는 이 환경에서 네트워크가 막혀 있다. 그래서 광고 지면은 빈 상태로 보였다.
  - 모든 수치는 로컬 측정값이고 실제 트래픽이나 전환율이 아니다. 운영 GA 데이터로 우선순위를 다시 확인해야 한다.
  - 이 문서는 문제를 짚기만 하고, 코드는 수정하지 않았다.

## 1. 퍼널

### 1-1. 입력 단계

**태어난 시각 미입력 시 제출 실패 (가장 심각)**

- 재현: 홈에서 1990 / 5월 / 15일만 입력하고 「오늘의 운세 보기」를 누른다.
- 결과: "태어난 시각을 입력하거나 '시간을 몰라요'를 선택해 주세요." 오류가 나고, `calc_start → form_error` 이벤트가 전송된다.
- 기본값이 「시각 입력」 탭이고 시각 칸이 비어 있어서, 시각을 모르는 사람도 일단 막힌다. 이 화면에는 결과 예시도 없어서 막힌 김에 떠날 이유가 충분하다.
- 제안
  - 시각을 비우면 '모름'으로 계산한다.
  - 결과 상단에 "시간을 넣으면 더 정확해져요 → 입력"을 표시한다.
  - 또는 탭 순서를 「모름 / 시진 / 정확한 시각」으로 바꾼다.

**성별이 '남성'으로 미리 선택됨**

- `src/site/birth-form.js:30`에서 `value="M" checked`로 되어 있다.
- 여성 사용자가 놓치면 대운 방향이 바뀐 틀린 결과를 받는다. 결과를 신뢰할 수 없게 되고 공유도 줄어든다.
- 제안: 기본 선택을 없애고 필수로 받거나, 최소한 결과 상단 요약 줄에 "남성 기준"을 노출한다.

**필드가 너무 많이 한 번에 보임**

- 단일 계산기는 입력·선택 요소가 16개, 궁합은 31개다.
- 양력/음력, 윤달, 시각/시진, 시각, 모름, 이 기기에 저장, 저장된 정보 모두 삭제, 저장 안내 2줄, 시간 보정 안내까지 첫 화면에 다 나온다.
- 홈은 표시 이름을 접어 두었지만, 다른 계산기 페이지는 펼친 상태다.
- 제안: 첫 화면에는 생년월일, 성별, 시각(모름 기본) 세 줄만 둔다. 나머지는 「추가 옵션」으로 접는다.

- 제안
  - 소개문은 2줄로 줄인다.
  - 일진 박스는 폼 아래나 결과 쪽으로 옮긴다.
  - 안내 카드는 폼 위 한 줄짜리 링크로 바꾼다.

### 1-3. 결과 단계

`/today/` 결과 화면(모바일)의 구성 요소별 세로 위치다.

| 요소 | 세로 위치(px) |
|------|------:|
| 결과 도착 지점(자동 스크롤) | 1,212 |
| 행운색 쿠팡 배너(높이 320) | 2,080 |
| 이어서 살펴보세요 | 8,120 |
| 결과 공유 | 8,318 |
| 입력 폼(다시 나타남) | 8,524 |
| 공통 쿠팡 배너 | 9,436 |
| 공개 예시(가상 사례) | 10,164 |
| 문서 끝 | 14,025 |

- **공유와 다음 행동이 너무 멀다.** 요약 카드에서 공유까지 7,000px 넘게 내려가야 한다. 분야 칩(종합·직장운…)이 있어도 7개 분야 카드가 모두 펼쳐져 있다.
  - 제안: 요약 카드 바로 아래에 「공유 · 이미지 저장 · 내일 운세」 행을 둔다. 분야 카드는 접힌 상태(제목·점수·한 줄)로 시작한다.
- **광고가 핵심 콘텐츠 사이에 끼어 있다.** 요약 → 행운 정보 → 광고 고지 2줄과 320px 배너 → 분야별 운세 순서다. 광고가 비거나 차단되면 빈 박스로 남는다(캡처에서 확인).
  - 제안: 행운색 배너는 분야 카드 뒤로 보낸다. 빈 지면은 접는다(`data-ad-state="unavailable"`일 때 높이 0).
- **이어서 볼 콘텐츠 추천이 약하다.** `src/site/tool-navigation.js:19-20`에서 홈과 오늘 결과 다음 추천이 내일·주간·월간뿐이다. 그림이 있고 공유하기 좋은 「인생 캐릭터」, 「사주 랭킹」이 빠져 있다.
  - 제안: 오늘 → 인생 캐릭터 · 랭킹 · 내일.
- **'가상 사례'가 내 결과와 섞인다.** 내 결과(64점) 아래에 같은 형식의 「실제 엔진으로 계산한 가상 사례」 점수표(55점)가 또 나온다.
  - 제안: 결과가 있을 때는 예시 섹션을 숨기거나 맨 아래 접힌 상태로 둔다.
- **입력 폼이 결과 밑에 다시 통째로 나온다.** 결과 화면에서는 「입력 정보 수정」 버튼 하나면 충분하다.

### 1-4. 공유 · 재유입 단계

- **카카오 버튼**: `VITE_KAKAO_JS_KEY`가 빌드에 없으면 숨는다. TODO.md 4번이 미완료 상태다. 한국 사주 서비스에서 가장 중요한 공유 채널이므로 운영 빌드에 들어갔는지 확인이 필요하다.
- **공유 랜딩(`/share/`)**: 카드와 CTA 구성은 좋다. 다만 다음 두 가지가 아쉽다.
  - CTA 아래 추천 카드 4개의 설명이 모두 "무료로 바로 확인"으로 같다.
  - 랜딩 화면 안에 입력 폼이 없어 계산기 페이지로 한 번 더 이동해야 한다. 생년월일 3칸을 랜딩에 바로 넣는 실험을 권한다.
- **이미지 저장**: 버튼이 강조색으로 가장 눈에 띈다. 하지만 공유 바 자체가 너무 아래에 있다(1-3 참고).

### 1-5. 재방문 단계

- **저장이 기본 꺼짐**: 저장하지 않으면 탭을 닫는 순간 입력이 사라진다. 저장 체크박스는 폼 하단에 16px 크기로 있다.
  - 제안: 첫 결과 직후 "다음에 바로 보기: 이 기기에 저장" 같은 결과 내 1클릭 CTA를 둔다. 개인정보 정책상 기본값을 켤 수 없다면 이 방식이 최선이다.
- **재방문 화면은 좋다**: 저장 후 다시 오면 「불러온 출생 정보 → 이 정보로 오늘 운세 보기」 카드가 첫 화면에 나온다. 다만 홈 상단 문구는 처음 온 사람용 그대로다.
- **출석·연속 방문**: TODO.md 8번(게이미피케이션)은 아직 없다. 재방문 장치가 사실상 저장 기능 하나뿐이다.

## 2. 분석 (GA4 이벤트 설계)

### 2-1. 퍼널 이벤트의 의미가 흐림

| 문제 | 내용 | 위치 |
|------|------|------|
| `calc_submit`이 검증 통과 후에만 전송됨 | 검증 실패 시 바로 return하므로 `calc_submit ≈ calc_result`가 된다. 제출 → 결과 단계를 볼 수 없고, 실패한 제출 시도는 `form_error`에만 남는다 | `src/client/tool.js:352-357` |
| `calc_result`가 페이지 이동마다 자동 발생 | 세션에 입력이 있으면 계산기 페이지를 열 때마다 `calc_origin=session_restore`로 전송된다. 오늘 → 랭킹 → 인생 캐릭터만 이동해도 `calc_result` 3회. 핵심 이벤트로 잡으면 부풀려진다 | `src/client/tool.js:228, 238` |
| `calc_origin` 값과 문서 불일치 | 코드 값은 `form`·`session_restore`·`device_restore`·`legacy_restore`·`date_refresh`다. README에는 `form`·`saved`·`sample`로 적혀 있어, 이 문서를 보고 탐색 보고서를 만들면 필터가 비게 된다 | README "GA4 이벤트" 표 |
| 이벤트명 이중화 | README가 `calc_result → fortune_view` 수정 규칙 가능성을 언급한다. 어느 이름으로 쌓이는지 운영 속성에서 확정해야 한다 | README |

**제안**

- 버튼 클릭 시점에 `calc_attempt`(검증 전)를 보내고, `calc_submit`은 지금처럼 검증 통과를 뜻하게 한다.
- 전환 지표는 `calc_result` 중 `calc_origin=form`만 쓴다. 또는 사용자가 직접 계산한 경우만 `calc_complete`로 분리한다.
- 퍼널: `page_view → calc_start → calc_attempt → calc_submit → calc_complete → result_view → share`

### 2-2. 수집 안 되는 핵심 행동

| 행동 | 현재 | 필요한 이유 |
|------|------|------------|
| 랭킹 「내 순위 공개」 클릭 | 없음 | 랭킹 퍼널의 핵심 단계 |
| 분야 칩(직장운·금전운…) 클릭 | 없음 | 어떤 분야를 읽는지 알아야 콘텐츠 투자처를 정할 수 있다 |
| 「이 흐름이 나온 이유」·「해석 근거와 전날 비교」 펼치기 | 없음 | 근거 콘텐츠의 가치 측정 |
| 「이 기기에 저장」 체크, 저장 성공 | 없음 | 재방문 퍼널의 입구 |
| 저장한 사람 추가·선택 | 없음 | 가족 단위 사용 측정 |
| 인생 캐릭터 카드 상세 열기 | 없음 | 가장 공들인 콘텐츠의 소비량 |
| 결과 스크롤 깊이 | 없음 | 14,000px 페이지에서 어디서 이탈하는지 |

`result_view`는 첫 제목이 50% 보이는 시점만 잡는다. 결과 내부에 25·50·75·100% 지점 또는 섹션 단위의 `result_section_view`를 권한다.

### 2-3. 맞춤 정의 누락

코드는 보내는데 TODO.md 2번 등록 목록에 없는 매개변수가 있다. 맞춤 측정기준으로 등록하지 않으면 보고서에서 쓸 수 없다.

- `entry_point`, `entry_source`
- `reading_date`, `usage_date`, `measurement_version`
- `ad_slot`, `ad_context`, `ad_provider`, `ad_layout_version`, `ad_placement`
- `completion_type`, `page_path`

### 2-4. 기타

- **공유 유입 추적**: 공유 URL은 `/share/?k=today&s=64&h=…&d=…`다. UTM이 없어 카카오·복사·X 유입이 GA에서 대부분 Direct·Referral로 흩어진다. `utm_source=kakao|copy|x|facebook&utm_medium=share&utm_campaign=<tool>`을 권한다. `page_location` 필터가 이미 UTM을 허용하므로 코드 수정은 공유 쪽만 하면 된다.
- **광고 측정**
  - `ad_slot_view`는 지면 도달이고, 클릭·수익과 연결되지 않는다.
  - 쿠팡 배너 설정의 `tsource`가 비어 있다(`src/site/partner-ad.js:7`, `src/client/lucky-colors.js:26`). 지면별(`common`, `lucky`)·도구별로 `tsource`를 나눠 넣으면 파트너스 리포트에서 지면 성과를 구분할 수 있다.
- **동의 모드**: Consent Mode 설정이 없다. 영어판으로 EEA 유입을 받는다면 GA4 Consent Mode v2와 애드센스 CMP를 함께 켜야 한다.
- **문서 정합성**: README 이벤트 표를 코드 기준으로 다시 맞춰야 한다. 표에 없는 이벤트는 `share_complete`·`share_handoff`·`share_cancel`·`share_failed`, `saved_result_open`, `calendar_day_open`, `share_landing_view`다.

## 3. 디자인

### 3-1. 정보 구조

- **홈이 텍스트 카드의 나열이다.** 모바일 홈 높이는 9,301px이고, 같은 메뉴가 「운세와 사주 둘러보기」 3개 → 「무료로 보는 사주와 운세」 카드 10개 → 푸터 링크로 세 번 반복된다.
- **가장 매력적인 콘텐츠가 묻혀 있다.** 인생 캐릭터(일러스트 60종)와 사주 랭킹이 텍스트 카드 10개 아래 「재미로 보는 사주」에 있다.
  - 제안: 폼 바로 아래에 캐릭터 그림 2~3개를 쓴 큰 카드로 올린다.
- **첫 화면에 결과에 대한 기대를 만드는 요소가 없다.** 폼만 있고 결과 미리보기나 그림이 없다. 「오늘 운세 결과 예시 보기」 링크는 폼 맨 아래에 있다.
  - 제안: 폼 옆(PC)이나 위(모바일)에 점수 링과 제목이 보이는 결과 카드 썸네일을 둔다.

### 3-2. 시각 · 타이포그래피

- **작은 글씨 비중이 높다.** 결과 화면 본문 글자 수 7,904자 중 13px 이하가 25%, 14px 이하가 37%다. "점수는 성공 확률이 아닙니다"류의 고지와 안내가 많아 화면이 회색 잔글씨로 덮인다.
  - 제안: 고지는 한 곳으로 모으고, 반복 문구를 줄인다.
- **결과 영역에 남색 테두리가 보인다.** 결과로 포커스를 옮길 때(`#reading-summary`) 2px 아웃라인이 마우스·터치 사용자에게도 보인다(모바일·PC 캡처 모두). 큰 남색 박스가 결과 전체를 감싸 오류처럼 보인다.
  - 제안: `:focus:not(:focus-visible) { outline: none }` 또는 `tabindex=-1` 대상에만 아웃라인 제거.
- **광고 고지 정렬**: 「광고 · 쿠팡 파트너스」 라벨과 고지 문구가 카드 바깥 왼쪽 끝에 붙어 있어 본문 카드 정렬과 어긋난다.
- **다크 모드**: 기본 버튼(밝은 보라 배경, 검정 글자)이 다른 요소보다 지나치게 밝아 튄다.

### 3-3. 터치 · 접근성

모바일 결과 화면의 터치 요소 124개 중 55개가 가로나 세로 40px 미만이다. 대표 사례:

| 요소 | 크기(px) |
|------|------|
| 정보 아이콘 (i) | 17~18 × 17~18 |
| 체크박스 (윤달 · 시간 모름 · 기기 저장) | 16 × 16 (라벨 포함 클릭은 가능) |
| 언어 전환 「한국어 / English」 | 높이 36 |
| 이동 경로 「홈」 | 12 × 19 |
| 「결과 예시와 읽는 법」 링크 | 높이 19 |
| 십신 태그 (겁재 · 비견 …) | 21 × 18 |

### 3-4. 헤더 · 내비게이션

- 모바일 상단 메뉴에서 「저장한 사람」이 두 줄로 꺾인다.
- 「전체 +」 메뉴의 15개 항목 중 '오늘의 운세'만 선택 배경이 있어, 현재 위치 표시와 버튼처럼 보이는 효과가 섞인다.
- 상단 고정 메뉴는 「오늘 · 내 사주 · 궁합 · 저장한 사람」 4개다. 인생 캐릭터나 랭킹 같은 재미 요소로 가는 진입점이 상단에 없다.

### 3-5. 성능

| 항목 | 측정값 | 메모 |
|------|------|------|
| 웹폰트 CSS (Hahmlet + IBM Plex Sans KR + Noto Serif KR) | 압축 125KB / 해제 536KB | 렌더링 차단 `<link>`. 한글 서체 3종 동시 로드(`src/site/layout.js:171`) |
| 홈·계산기 초기 JS | 압축 339KB / 해제 970KB (13개) | 입력 전에 만세력 라이브러리(`lunar` 98KB, `birth-form` 112KB)까지 로드 |
| 백과 페이지 JS | 압축 14KB | 대조군 |
| CLS | 0 (로컬, 광고 미송출) | 운영에서 광고가 채워질 때 다시 측정 필요 |

**제안**

- 서체를 2종 이하로 줄이고, 본문은 시스템 폰트나 서브셋을 쓴다. `preload`와 `font-display: swap`을 점검한다.
- 계산 엔진(`lunar`·`birth-form` 청크)은 폼에 첫 입력이 들어오는 순간(`calc_start` 시점) 로드한다.
