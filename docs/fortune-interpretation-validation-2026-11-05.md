# 기간·분야 이동과 만세력 해석 차이 추가 검증

2026년 11월 5일. 포춘의 기간 이동과 분야 바로가기를 같은 위치에서 사용할 수 있게 정리하고, 강약·용신·대운의 실제 계산 근거를 결과에서 펼쳐 보도록 추가했다. 기존 계산값과 골든값은 유지했다. 이전 [8개 서비스 비교](fortune-reference-2026-11-05.md)의 P1 두 항목을 이어서 진행한 기록이다.

## 사용 흐름에 반영한 내용

- 결과 위에 오늘·내일·이번 주·이달·올해·내년을 배치했다. 선택한 인물과 보고 있던 분야를 유지한다. 예를 들어 엄마의 금전운에서 이번 달을 누르면 같은 인물의 월간 금전운으로 이동한다.
- 종합과 7개 분야의 바로가기 형식을 기간별로 통일했다. 현재 기간·분야를 표시하며 키보드로 이동하면 실제 결과에 초점을 옮긴다. 주간·월간 달력 안의 하루 상세는 바깥 기간 결과와 구분한다.
- 사주·궁합 등 다른 풀이는 접어서 제공하고, 기존 이어보기와 읽기 설정은 유지했다. 생년월일·이름은 이동 주소나 분석 이벤트에 추가하지 않는다.
- 원국의 ‘강약·용신·대운은 어떻게 정했나요?’를 열면 가중 합계, 판정 구간, 오행 선호도, 계절 가산, 순행·역행, 대운 시작 연도와 현재 구간을 볼 수 있다. 한국어·영어 모두 적용했다.
- 대운 표의 기존 ‘만 나이’ 설명을 실제 구현과 맞췄다. 표시값은 시작 연도−출생 연도이며, 대운은 해당 시작 연도부터 적용된다. 정확한 교체 월·일로 전환하는 계산은 아니다.

## 비교 조건과 확인 범위

실존 인물의 정보가 아닌 양력 1990년 5월 15일을 공통 예시로 썼다. 기본 시각은 12:00, 기본 성별은 남성이다. 포스텔러는 서울특별시를 선택하고 야자시·조자시 및 합화 옵션을 끈 상태에서 비교했다. 새로 확인한 것은 보정 옵션 전후, 여성 역행, 23:31 경계 사례다. 로그인·결제는 하지 않았다.

비교 대상의 결과는 공개 화면을 직접 조작해 확인했다. 포춘은 같은 입력의 엔진 반환값 및 화면을 대조했다. 서비스 간 일치 여부는 계산 규칙을 비교하는 자료이며 미래 예측 정확도의 검증은 아니다.

## 같은 명식에서도 보정 옵션에 따라 강약이 바뀐다

12:00 남성의 네 기둥은 포춘·포스텔러·척척 모두 년주 庚午, 월주 辛巳, 일주 庚辰, 시주 壬午였다.

| 비교 | 목·화·토·금·수 표시 | 강약 | 용신 표시 |
| --- | --- | --- | --- |
| 포스텔러, 조후·궁성 보정 끔 | 0·37.5·12.5·37.5·12.5% | 중화신약 | 조후 수 / 억부 토 |
| 포스텔러, 조후·궁성 보정만 켬 | 0·50.0·13.6·27.3·9.1% | 신약 | 조후 수 / 억부 토 |
| 포춘 | 겉글자 수 0·3·1·3·1 | 신강 | 용신 화 / 희신 수 |

포스텔러의 동일 입력에서 옵션 하나만 바꾸어 강약 변경을 확인했다. 해당 서비스의 도움말은 월지·일지 등 위치 가중치와 계절·시각의 조후 보정을 설명하지만, 확인한 화면에 전체 수식과 강약 경계값은 공개하지 않았다. 따라서 보정이 결과를 바꾼다는 점은 확인했지만, 포춘과의 차이 중 각 가중치가 얼마나 기여하는지는 분해할 수 없다. [포스텔러 만세력 결과 및 보정 도움말](https://pro.forceteller.com/)

포춘의 같은 원국은 비겁 2.7, 식상 1.15, 재성 0.45, 관성 3, 인성 2.2이다. 일간을 돕는 비겁+인성 4.9를 전체 9.5로 나누면 약 51.6%가 된다. 포춘의 47% 이상~64% 미만 구간이므로 신강이다. 이 수치는 사람들의 분포나 예측 성공률이 아니라 원국 가중치의 비율이다.

포춘은 일간 자신의 천간을 강약 합계에서 제외한다. 다른 천간은 각 1, 지장간은 배정 일수/30에 년지 1·월지 3·일지 1.5·시지 1을 곱한다. 강약 경계는 19·35·47·64%, 용신 방향을 정하는 억부 경계는 별도로 41%다. ‘중화’라고 표시되는 일부 원국도 억부 방향이 다를 수 있으므로 두 기준을 구분해 설명했다.

용신은 억부 선호도에 제한적인 계절 가산을 더한 순위다. 이 예시의 최종 선호도는 목 1.1, 화 1.9, 토 −1.1, 금 −1.4, 수 1.7이다. 여름인 사월에 겉글자 수가 1개여서 수에 +0.7이 적용됐지만 화 1.9가 더 높아 용신 화·희신 수가 된다. 이 합산 방식은 포스텔러처럼 억부용신과 조후용신을 별도로 표시하는 방식과 직접 일치하지 않는다. 포춘은 용신 선정에 별도 격국·종격·합화 판정을 적용하지 않는다.

시각만 23:31로 바꾸고 남성·양력 날짜를 유지했다. 아래는 모두 실제 결과를 확인한 값이다.

## 대운은 방향·시작 연도·나이를 나누어 비교한다

| 입력 | 포춘의 환산 간격과 첫 대운 | 척척에서 확인한 첫 대운 |
| --- | --- | --- |
| 1990-05-15 12:00 남성 | 순행, 7년 3개월 0일 / 1997년 壬午 / 표시 나이 7 | 7살 壬午 |
| 1990-05-15 12:00 여성 | 역행, 3년 1개월 20일 / 1993년 庚辰 / 표시 나이 3 | 3살 庚辰, 이후 己卯·戊寅·丁丑 |

여성으로 바꾸어 첫 간지와 역행 순서를 추가 확인했다. 척척의 첫 대운 시작 연도는 이번 화면 대조에서 독립적으로 확인하지 않았으므로 표시 나이만으로 포춘과 전환 시점까지 같다고 결론내리지 않는다.

척척의 공개 안내는 양년 남성·음년 여성은 순행, 반대는 역행이며, 순행은 다음 절기·역행은 이전 절기까지의 날짜를 3으로 나누는 정운법을 설명한다. 나머지가 0 또는 1이면 버리고 2면 올리는 규칙도 제시한다. 포춘에 설치된 lunar-javascript 1.7.7의 `lunar.js`에서 `getYun` 기본 방식(sect 1)은 날짜와 시진의 차이를 함께 환산하는 것을 확인했다. ‘3일=1년’이라는 계열이 같아도 시간 처리와 반올림이 다르면 시작값이 달라질 수 있다. [척척의 대운 계산 안내](https://sajuplus.com/cheokcheok-calendar), [라이브러리 공식 저장소](https://github.com/6tail/lunar-javascript)

포춘의 남성 예시 대운은 1997 壬午, 2007 癸未, 2017 甲申, 2027 乙酉 순서다. 2026년 화면에는 2017~2026년의 甲申을 적용한다. 기존 신한라이프 대조에서는 2026년에 37살 乙酉가 강조됐고, 포스텔러 연도 표의 첫 구간에는 1996이 표시됐다. 경쟁사의 정확한 전환일·나이 산식이 충분히 공개되지 않아 연도 차이의 원인을 확정하지 않았다.

이번에 수정한 것은 포춘의 표시 설명이다. 기존 숫자는 생일 기준 만 나이가 아니며 시작 연도−출생 연도다. 출생년을 1세로 세는 방식과도 다르다. 정확한 교체일을 쓰는 방식으로 변경하려면 점수에 적용하는 대운까지 달라지므로 별도 엔진 변경과 검증이 필요하다. 시간 미상은 시주를 제외하고 절기·대운에서 정오를 참고한다는 점도 결과에 표시했다.

## 검증과 남은 범위

기존 계산 보존 여부는 변경 전후 가상 원국 300개와 일간·연간·평생 풀이 900개를 비교했다. 새로 추가한 근거 메타데이터를 제외한 기존 반환값이 모두 일치했다. 계산 상수는 공통 모듈로 옮겼지만 값은 변경하지 않았다.

새 화면 테스트는 한국어·영어 기간 이동, 선택 인물·분야 유지, 실제 점수, 키보드 초점, 주간 날짜 상세와의 ID 충돌, 역행·시간 미상, 320~1440px 화면 폭, 자바스크립트 없는 계산 기준 문서까지 다룬다.

최초 전체 실행에서는 브라우저 광고 B 배치의 노출 이벤트 검사 하나가 5초 시간 초과로 실패했다(183개 통과). 앱 코드를 변경하지 않고 해당 A·B 검사를 각각 3회 실행해 6회 모두 통과했고, 이어 전체 재검사 184개가 모두 통과했다. 원인은 확정하지 않았으며 재현되지 않은 간헐 실패로 기록한다. 새 테스트의 창 너비 표기 두 곳에 있던 lint 오류는 `window.innerWidth`로 명시해 수정했다.

PR #39의 첫 GitHub CI에서도 같은 광고 B 검사가 실패했다. 기존 검사는 계산 후 자동 스크롤 중에 위치를 직접 지정하고 실제 노출 위치는 확인하지 않은 채 이벤트를 기다렸다. 후속 보강에서는 이벤트 구분·중복 검사에서 안정된 요소로 이동하는 `scrollIntoViewIfNeeded()`를 사용하고, 광고가 화면에 100% 들어온 것을 확인한 뒤 집계를 검증한다. 50% 노출 경계 검사는 그대로 유지했다. 제품의 광고 배치·집계 코드는 변경하지 않았으며, 비공개 엔진 문제와는 별개의 브라우저 검사 보강이다.
